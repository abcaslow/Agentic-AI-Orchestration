[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] This page contains a list of reports that you can run and customize. ITPIE comes with nearly 20 reports that are already built. You are free to modify these reports to your liking, or use them as the foundation for your own reports.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Most reports that come provided with ITPIE are based on a single search source, such as "find device." One exception is the "End of Product Sale (EoPS) / End of Service Life (EoSL)" report, which combines the "find inventory" search results with the Network Data "Find EoPS/EoSL" source to show which products are approaching their manufacturer-defined end of service life. Note that the Network Data source must be populated by the user in order for this source to be effective. See the Network Data documentation for more information.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] You can create folders to organize your reports. Folders are completely optional: you do not have to use them, but they are available if you have a lot of reports that makes it difficult to find what you want.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] To create a folder, click on the "Add Folder" button. A drawer will open on the right side of the page prompting you for the name of the folder and its parent. You can add a folder directly under another folder by selecting an existing parent; if you leave the "parent" field blank, your folder will be created at the root level.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] To add reports to a folder, you can use the drag handles on the left to click and drag the report into the folder. If you drop the report outside of an existing folder, it will be moved to the root level. Alternately, you can click on the "More..." menu dropdown and select "Move," which will give you a dropdown list of existing folders where you can move the report (including 'None', which will move it to the root level). Folders can be moved in the same way: by drag and drop, or by clicking on their "More..." button and selecting a new parent.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Note: you cannot use the Move action to send a folder into one of its child folders. (You can, however, send a folder up to another layer in its root folder's hierarchy.) If you delete a folder, all of its children (reports and folders) will move one level up in the hierarchy. For example, if you deleted the "Route Reports" folder in the screenshot at the beginning of this section, all of the route reports under it would be placed at the root level (i.e., with no parent folder).

[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] On the report page itself, you can "Reload" the report's fields. [ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Finally, you can delete the report by clicking on the "Delete" button. [ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Joins Tab
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Select the join type from the Join Type drop-down menu:
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] This field is required.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] FULL JOIN : This join creates the result-set by combining results of a LEFT JOIN and RIGHT JOIN. The result-set will contain all the rows from both tables. The rows where there is no match, the result-set will contain NULL values.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] LEFT JOIN : This join returns all the rows of the table on the left side of the join and matching rows for the table on the right side of join. The rows for which there is no matching row on right side, the result-set will contain null.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] RIGHT JOIN : Similar to LEFT JOIN. This join returns all the rows of the table on the right side of the join and matching rows for the table on the left side of join. The rows for which there is no matching row on left side, the result-set will contain null. RIGHT JOIN is also known as RIGHT OUTER JOIN.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] INNER JOIN : The most restrictive type of join. This join returns only rows that match in both sources.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] After choosing a join type, you define which fields you are trying to match in your two sources. You will select one field from the left-hand source, one from the right-hand source, and a join operator.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Equals : This means that the two fields must have the same string representation. The comparison is case insensitive.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Equals Single IP : The same as "equals," but both fields must be an IP address. There is no way at the time to cast from a string to an IP address.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Contains : This operator is a more flexible string matcher: the value in the second field must appear somewhere in the first field (e.g., if the first field is "Hostname," the second field would match if its value was "host" or "name" or "hostname", but not if it is "hostnames"). Like the "equals" operator, case does not matter.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] In List : For this operator to match, the first field must contain a comma-separated list of values, and the second field must equal one of the values between commas.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] In Subnet : This operator uses normal networking logic to determine if the second field is an IP address in the first field. Note that the first field must be a subnet type, and the second field must be a single IP address.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] To negate any of these ("not equals," "does not contain," etc.), select NOT from the dropdown in front of the operator.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Filters Tab
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] The tables selected in the custom report can be filtered before being joined. Fields from either table can be selected and a filter applied using a user provided value.
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Filters support the same types as joins, plus two additional types:
[ITPIE:OPS Documentation | Custom Reports | https://itpie-hostname/documentation/content/features/custom-reports.html] Within Date : Includes only records that are within the provided number of days from today.
