[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] For details on the related authentication and security settings, see Authentication .
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] A user may log in to the application with a local user account or via an external identity provider .
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Login
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] The login form allows a user to login with an email and a password. Several statuses prevent a user from logging in.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Disabled : Users are not deleted, but may be enabled or disabled by a super user. A disabled user may not log in.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Locked out : Users may be locked out if they fail to login correctly a configured number of times. Lock out may expire in a configured time period or the user may be unlocked by a super user.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Inactive : Users may be deactivated if they do not log in and use the application in a configured time period. The user may be reactivated by a super user. Reactivation is also subject to an inactivity period.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Maximum active sessions : Users may log in a configured maximum number of times. Sessions may expire automatically in a configured time period. If the user cannot explicitly log out of active sessions or cannot wait for session expiration, a super user may remove all active sessions for a user.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Expired password : Users may not log in if their password has exceeded a configured expiration time period. The user should be redirected to the change password form, where other configured password validations should be in effect. After changing the password, the user should complete a log in with the new password.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] One-time use password : Users may not log in if their password is one-time use. The user should be redirected to the same change password form and should complete a log in with the new password.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Change password
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] The user should be redirected to the change password form as a result of a log in with an expired or one-time use password. Password validations should be enforced, based on the current configuration.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Required length : The new password should use be a required minimum length.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Required complexity : The new password should use a certain number or combination of lowercase and uppercase alphanumeric and special characters and an overall number of unique characters.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Required change : The current password and the new password should differ by a required number of characters.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Prohibited reuse : The new password should not match one of the user's recent previous passwords.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] New password : A new password cannot be changed within a minimum time period. This restriction does not affect changing a one-time use password.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] External login
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Note
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Any state information exchanged by the external identity provider and the client in visible locations, such as in the URL query string, should be secured with data protection .
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] A button for each configured external identity provider should be displayed on the log in form, which, when clicked, should redirect the user to the provider's remote log in endpoint. If the external log in is succesful, the user should be redirected back to the application. User status checks should run, as for a local user log in, with the exception of any password-based checks.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] A successful external login must be associated with a local user.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] The application looks for a user already associated with this external login.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] If none is found, the application looks for a local user with the email returned by the login provider and associates it.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] If none is found, the application creates a new user with the email returned by the login provider and associates it.
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Sessions
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] Note
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] The session key, exchanged between server and the client's browser in a cookie, should be secured with data protection .
[ITPIE:OPS Documentation | Authentication | https://itpie-hostname/documentation/content/administration/authentication.html] A user login should create a new active session and logout should delete that active session. If a session's IP address changes during its lifetime, the session will be removed and the user will be logged out. Sessions may participate in both sliding and absolute expiration, depending on application configuration. If an active session continues to be used through half or more of its sliding expiration lifetime, it should be renewed for another period up to the absolute expiration lifetime.
