[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Explanation of Grouping behavior:
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Grouping adheres to the following behavior: If a node has one neighbor, that node is considered a leaf node and will be included in the set of nodes that are next in line to be collapsed into their parent. A node either be a device or a collection of devices that form a group. All leaf nodes across the entirety of the map are considered to be one level of nodes, and each level of nodes can consist of one or more connected clusters (or groups). Once a set of leaf nodes has collapsed into its parent, the resulting group created from the set of leaf nodes and its parent is now considered a new leaf node.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] There are three grouping modes used to determine which grouping levels will be collapsed into combos:
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Number of Levels - in this mode, the user will select a number of levels to collapse. Any node that has a grouping level less than or equal to the selected number of levels will be collapsed into its parent.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Node Threshold - this mode works the same way as the previous mode, except the number of levels will be determined automatically by increasing the number of levels grouped until the number of uncollapsed nodes on the canvas is below the specified threshold. Note that the number of uncollapsed nodes will likely not be equal to the threshold value, as the grouping still adheres to a "by-the-level" methodology.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Collapse Unmanaged - when selected, any unmanaged host that has exactly one relationship is collapsed into a combo for its parent device, regardless of grouping level.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Additionally, there are two more options to let users further customize grouping behavior:
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Orphans checkbox: when enabled, create a single combo that contains all orphaned nodes (nodes that don’t have any relationships) on the map.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Endpoints checkbox: when enabled, any endpoint - a phone, for example - that has exactly one relationship is collapsed into a combo for its parent device, regardless of grouping level or mode.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Layouts
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Maps can be viewed in several different layouts. Force-directed layouts include the Standard , Organic , Structural , and Lens layouts. There are two hierarchical layouts, Hierarchical and Half-Square Hierarchical .
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Standard
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] The standard layout constructs the graph so links are a consistent length, with nodes and edges overlapping as little as possible and distributed evenly across the chart.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Its consistency and simplicity helps make it a good catch-all for any kind of data and any size of dataset. It is particularly useful for finding patterns and symmetries.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] If the layout button is pressed while nodes are selected, the layout change will only be applied to those nodes.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Organic
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] The organic layout is a force-directed layout designed specifically for the biggest data-sets.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] It detangles complex networks by spreading nodes and links apart, so multiple components are laid out in a circular arrangement with larger components in the center. The pattern is easy to understand and helps reveal underlying structures.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] If the layout button is pressed while nodes are selected, the layout change will only be applied to those nodes.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Structural
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] The structural layout is similar to the standard layout, except it groups nodes with similar attributes together in fans. It is particularly useful to get an overview of the network clusters or to identify groupings that may not be obvious.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] If the layout button is pressed while nodes are selected, the layout change will only be applied to those nodes.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Lens
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] The lens layout is similar to the standard layout, but is more compact by fitting the nodes within a circular envelope.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] If the layout button is pressed while nodes are selected, the layout change will only be applied to those nodes.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Tweak
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] This layout makes small changes to the nodes, modifying the layout that is already in place. Not recommended for use with any of the hierarchical layouts.
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Hierarchical
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] The first hierarchical layout aims to highlight the main direction or flow within a directed graph. This layout arranges the nodes in such a way to minimize edge crossings. If this layout is run with devices selected, those devices will be placed on the top of the layout.

[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] Data Snapshot
[ITPIE:OPS Documentation | Maps | https://itpie-hostname/documentation/content/features/maps.html] The user can choose three views of the underlying data that populates the map: 1) the most recent current data, 2) the state of the data at the time of last save, or 3) a diff that highlights changes made since the map was last saved.
