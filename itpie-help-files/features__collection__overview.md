[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] This section provides instructions on how to use the Collection feature of ITPIE.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Note
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Network Usage
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] The ITPIE Collection feature uses a variety of protocols to collect data. We take special care to keep our network utilization low and the commands and api endpoints we query safe. As with any operation that uses the network in an automated fashion, without proper planning, impacts to network performance can arise. Its useful to consider when and how often you run automated collections to avoid running heavy collections during peak usage hours.

[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] ITPIE models a set of devices for collection using the following terminology:
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Glossary
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Credential Authentication details required to connect to a device or platform for collection. The properties of a Credential is platform-dependent. For example, SSH devices require a username and password, while AWS requires an Access Key and Secret Key. Where possible, ITPIE uses the platform-specific terminology.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Target A set of platform-specific connection endpoints for ITPIE. In most cases, this is simply an IP (or multiple IPs) that ITPIE should connect to. Some collectors, such as AWS, expect a region. Targets also allow configuration of protocol-specific properties, such as port, certificate verification, and the like, when available.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Jobs A group of Targets which can be scheduled for repeated execution, a single execution, or manually run ad-hoc. If supported by a particular collector type in a Target, Jobs can also change the amount of work done. For example, the SSH collector supports running a subset of commands and those subsets are configured on the Job as a Job Type.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Endpoint A specific device within a Target.

[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Tutorial - Configuring a Collection
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] The network to be configured in this tutorial has the following devices:
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] 172.28.1.30 - A 24 port Cisco 2960g switch named sw-office
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] 172.28.1.31 - A 24 port Cisco 2960g switch named sw-livingrm
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] 172.28.1.32 - An 8 port Cisco 2960g switch named sw-gaming
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] All of our switches use the same username and password and require privilege elevation for a successful collection. In your network, you may not have all this information up front and ITPIE provides tools to help you discover them as you go. This capability of ITPIE is outside the scope of demonstrating the Collection configuration.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] The first step is to configure Credentials. Navigate to the Credentials screen.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Click "Create Credential" and the credential management panel will expand from the right side of the screen. Note the default Collector Type is SSH. Name this credential something useful in the Label input, then provide a username and password.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Repeat the process, but this time, indicate it is a privileged credential.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Note
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Privileged Credentials
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Privileged credentials are a property on the SSH collection type and do not apply to all networks. If you have credentials that are automatically authorized at a high privilege level, you will not need to use these. However, for our example network, the user user must first execute enable to gain sufficient privileges. ITPIE handles this privilege escalation when configured to do so.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Depending on the configuration of your network, you may or may not need to provide a username. If your network is configured to only request a password when escalating, then this username will be ignored. The network for this tutorial does not request a username when performing privilege escalation. Our recommended practice in this scenario is to put enable as it has a well-understood meaning in the context of network operations.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Next we need to associate these credentials with Targets. Navigate to the Targets screen by clicking the appropriate navigation link at the top, then click Create Collection Target.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] As with Credentials, the Collector Type defaults to SSH. There are many Collector Types available. Give this Collection Target a good Label and provide some IP addresses.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Input IP addresses (1, below) one per line as:
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Single addresses (e.g., 192.168.0.1)
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Subnets (e.g., 192.168.0.0/24)
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] IP address ranges (e.g., 192.168.0.1-50)
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Note
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Subnets and IP ranges with large blocks of unused IPs are not recommended for networks with over 100 devices. ITPIE will attempt to login to each IP and if it is usused, it will have to wait until it times out, leading to excessive collection times.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] The IP Mode and Subnet Mode buttons will expand or collapse the networks entered.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Next, select Credentials for this target. The selection widget allows multiple selection by single-clicking on items you wish to move. For our example, we can also simply click 'All' as these are the only configured.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Once your selection is decided, click the Add > button to move them to the selected column.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Finally, decide on an Elevation Strategy. This is optional and will only take effect if privileged credentials are associated with this target. "Automatic" is the default and should work in most circumstances.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Now that Credentials have been associated to Targets, ITPIE needs to know when to perform a collection on those Targets. Clicking on Jobs and then Schedule Collection Job will pull up the appropriate screen.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] We will be brought to a new screen with a side panel for entering the details. Name the job, then leave the Job Types selection on the default of "Job Types for Device". Please see Collection Job Types for more details on the Job Types feature. Click "Select All" underneath the Job Types selection to select all of the default job types.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Select an agent site from the "Agent Site" drop-down. Select the Internal agent site if you want to use the ITPIE server itself to perform the collection. If there are one or more collection agents authorized, there will be additional entries in this drop-down.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Click Save to confirm the job's settings.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] The next screen allows one to associate Targets and Schedules to a given Job. For the tutorial, we will be manually executing the Job, so a schedule is not needed. See Scheduling Jobs for more details on the Job Scheduling feature. For now, simply click on the Modify button in the Targets panel.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] On the Targets Association panel, select the Network Switches, then click "Add >" to move the selection to the Selected column. Then click Associate Targets.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] This will return us to the Jobs screen where the Targets will show up in the left-hand target association panel. Note that this shows the Name, description (if any), and the Collector Type for these targets. A job may use Targets of different Collector Types. As mentioned earlier, we will not be associating a recurring schedule for this Job. If we did, it would also show up here.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] The final step is to save the configuration by clicking Done in the upper right.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Now our Job will show up on the Jobs screen, indicating that it has never executed. Click "Run Now" to begin the collection process.

[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Import via Collection Files
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Network device information can be imported to leverage the ITPIE toolset against networks that are not directly accessible by ITPIE (e.g. air-gapped networks). [ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Multiple formats are accepted, including Collection files from the ITPIE Collection Engine (CE) and the ITPIE CLI Collector in the form of *.zip files.

[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] ITPIE performs maintenance actions related to data retention at the end of an import. Any data that falls outside the data retention windows will be removed.

[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] ITPIE will confirm success for all of the uploaded files, click Done to move back to the Jobs screen where your files will be importing.

[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] ARP : The ARP Job Type collects information related to ARP.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] MAC : The MAC Job Type collects information related to MAC addresses, specifically the MAC address tables (The MAC Job Type does not collect on interfaces or VLANs).
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Route : The Route Job Type collects information related to Routes.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Config : The Config Job Type collects the running configuration. Where applicable, the running configuration is stored in ITPIE for backup.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Discovery Performs a variety of lower-level scans and sweeps. This feature can cause strict intrusion-detection systems to view ITPIE as hostile or malicious. Similar to nmap but less aggressive.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Ping : Simple ICMP pings to each endpoint in the Targets list.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] NETBIOS : Queries each endpoint for NETBIOS information (Windows fileshares, etc)
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] SSH : Attempts an SSH connection; if successful, issues a graceful close of the connection. Even though ITPIE is gracefully closing the session (and never requesting a terminal) some devices still respond poorly to this if performed too frequently; use with caution.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] HTTP : Checks if port 80 is open.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] HTTPS : Checks if port 443 is open.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Statistics Useful for a light-weight collection that only gathers very specific kinds of data.
[ITPIE:OPS Documentation | Network Collection | https://itpie-hostname/documentation/content/features/collection/overview.html] Interface Statistics : The Interface Statistics Job Type collects interface, CPU, and memory statistics and skips secondary analysis by default. The InterfaceStatistics Job Type can not be run simultaneously with any other Job Type.
